# Requirement: Migrate CLI from Custom Arg Parser to commander.js

## Context
`src/cli.ts` currently implements a fully custom argument parsing layer: `extractFlagValue`, `parseOptionalIntegerFlag`, `parseProjectContextMode`, `parseForce`, and a hand-written `printUsage()`. This works but requires significant boilerplate per command, is fragile when new flags are added, and produces help text that diverges from community-standard UX. Migrating to `commander.js` removes all of that custom logic, auto-generates `--help` output for every command and subcommand, and lowers the maintenance cost for both contributors and users.

## Goals
- Replace the custom arg-parsing layer in `src/cli.ts` with `commander.js`.
- Preserve the exact public CLI interface (`bun nvst <command> [subcommand] [options]`) — no breaking changes for end users.
- Auto-generate `--help` output at the root level and for each command/subcommand.
- Delete the now-redundant helpers (`extractFlagValue`, `parseOptionalIntegerFlag`, `parseProjectContextMode`, `parseForce`, `printUsage`) once replaced.
- All existing automated tests continue to pass with no regressions.

## User Stories

### US-001: Root help auto-generated by commander.js
**As a** developer running `nvst`, **I want** `nvst --help` (and `nvst -h`) to print a structured, auto-generated help message **so that** I always see up-to-date usage without manually maintaining `printUsage()`.

**Acceptance Criteria:**
- [ ] `bun nvst --help` exits with code 0 and prints command/subcommand listing generated by commander.js.
- [ ] `bun nvst -h` produces identical output.
- [ ] Output includes all top-level commands: `ideate`, `start`, `define`, `refine`, `approve`, `create`, `audit`, `refactor`, `sync`, `init`, `destroy`, `write-json`, `write-technical-debt`.
- [ ] Typecheck / lint passes.

### US-002: Per-command/subcommand `--help`
**As a** developer, **I want** `nvst <command> --help` and `nvst <command> <subcommand> --help` to show scoped usage **so that** I can quickly look up flags for a single command without reading the full help.

**Acceptance Criteria:**
- [ ] `bun nvst create prototype --help` exits 0 and lists `--agent`, `--iterations`, `--retry-on-fail`, `--stop-on-critical`, `--force`.
- [ ] Every other command and subcommand responds to `--help` with its own scoped output.
- [ ] Typecheck / lint passes.

### US-003: All existing commands work identically after migration
**As a** developer using `nvst`, **I want** every command to behave exactly as before **so that** the migration is transparent to end users.

**Acceptance Criteria:**
- [ ] `bun nvst init` runs without error in a fresh directory.
- [ ] `bun nvst destroy` and `bun nvst destroy --clean` run without error.
- [ ] `bun nvst start iteration` runs without error.
- [ ] `bun nvst ideate --agent ide` runs without error.
- [ ] `bun nvst define requirement --agent ide` runs without error.
- [ ] `bun nvst refine requirement --agent ide --challenge --force` runs without error.
- [ ] `bun nvst refine project-context --agent ide` runs without error.
- [ ] `bun nvst approve requirement`, `approve prototype`, `approve project-context` run without error.
- [ ] `bun nvst create prototype --agent ide --iterations 2 --retry-on-fail 1 --stop-on-critical` runs without error.
- [ ] `bun nvst create project-context --agent ide --mode yolo` runs without error.
- [ ] `bun nvst audit prototype --agent ide` runs without error.
- [ ] `bun nvst refactor prototype --agent ide` runs without error.
- [ ] `bun nvst sync skills` runs without error.
- [ ] `bun nvst write-json` and `bun nvst write-technical-debt` run without error.
- [ ] Unknown commands/subcommands still print an error and exit with code 1.
- [ ] `bun nvst -v` / `--version` still prints the version string.
- [ ] Typecheck / lint passes.

### US-004: Custom arg-parsing helpers removed
**As a** contributor, **I want** the dead-code helpers removed **so that** the codebase is smaller and does not confuse future maintainers.

**Acceptance Criteria:**
- [ ] `extractFlagValue`, `parseOptionalIntegerFlag`, `parseProjectContextMode`, `parseForce`, and `printUsage` are deleted from `src/cli.ts`.
- [ ] No other file imports or references these removed functions.
- [ ] Typecheck / lint passes.

### US-005: Existing tests pass with no regressions
**As a** maintainer, **I want** the full test suite to pass after the migration **so that** no existing behaviour is silently broken.

**Acceptance Criteria:**
- [ ] `bun test` completes with 0 failures.
- [ ] No existing test files are modified to weaken assertions; only test setup that references removed helpers may be updated.
- [ ] Typecheck / lint passes.

## Functional Requirements
- FR-1: Add `commander` (latest stable) as a production dependency in `package.json` / `bun.lock`.
- FR-2: `src/cli.ts` must use a single root `Command` instance from commander.js; all commands are registered as subcommands or nested subcommands of it.
- FR-3: The `--agent` option (valid values: `claude`, `codex`, `gemini`, `cursor`, `copilot`, `ide`) must be registered as a required option on every agent-backed command/subcommand; commander.js validation replaces `parseAgentArg`.
- FR-4: `--force` must be registered as a boolean option on all commands that previously accepted it; commander.js replaces `parseForce`.
- FR-5: `--challenge` must be registered as a boolean option on `refine requirement` and `refine project-context`; commander.js replaces the manual `includes("--challenge")` check.
- FR-6: `--iterations <N>` (integer ≥ 1) and `--retry-on-fail <N>` (integer ≥ 0) must be registered on `create prototype` with custom parsing (`.argParser`) that replicates current validation; commander.js replaces `parseOptionalIntegerFlag`.
- FR-7: `--mode <strict|yolo>` must be registered on `create project-context` with a choices constraint; commander.js replaces `parseProjectContextMode`.
- FR-8: `--clean` must be registered as a boolean option on `destroy`.
- FR-9: `--schema <name>`, `--out <path>`, and `--data <json>` must be registered on `write-json`; stdin fallback behaviour must be preserved in the handler.
- FR-10: `--out <path>` and `--data <json>` must be registered on `write-technical-debt`; stdin fallback behaviour must be preserved.
- FR-11: `--version` / `-v` must continue to print the version string (use commander's `.version()` or a custom action to preserve the `NVST_COMPILED_VERSION` fallback logic).
- FR-12: On unknown commands or missing required arguments, commander.js must print an error and the process must exit with code 1 (no `process.exit()` — set `process.exitCode = 1`).
- FR-13: `GuardrailAbortError` must continue to be caught in the top-level `.catch()` and handled without re-logging.

## Non-Goals (Out of Scope)
- Changing command names, subcommand names, or flag names — the public interface is frozen.
- Adding new commands or flags not already in the current CLI.
- Replacing or modifying the individual command handlers in `src/commands/*.ts`.
- Adding a build step or bundler for commander.js.
- Migrating test infrastructure beyond making existing tests pass.
- Adding new tests for the commander.js integration (existing tests are the acceptance bar).
